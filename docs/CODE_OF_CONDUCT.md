# Code of conduct

This project discusses vulnerable devices in homes and buildings. Be precise, and do not turn a finding into a way to harm someone.

## Expected

- Critique the code and the spec. Leave the person out of it.
- Report a vulnerability in private. `packages/core/SECURITY.md` points at GitHub private vulnerability reporting. An email address is still an open question in `docs/QUESTIONS.md`.
- Assume good faith when a review disagrees with a threshold. The spec and the tests are the record.

## Not accepted

- Harassment, slurs, or personal attacks.
- Publishing someone else's traffic, credentials, or an unpublished vulnerability.
- Asking the project to block a device, build an exploit, or ship a detector that drops traffic. The library reports. The host decides.

## Questions

Open `docs/QUESTIONS.md` for a spec question. For a conduct problem, contact the maintainers through the same private channel as a vulnerability report until a public contact exists.
